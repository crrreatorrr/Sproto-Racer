# Car Stats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every car one of six classes with five stats (Speed, Acceleration, Turning, Boost, Luck) that
are shown as bars and balanced by AI races.

**Architecture:**
- `src/car-classes.js` holds the class bars and turns bars into multipliers.
- `src/roster.js` merges each car's class into its roster entry. That entry is already the kart's `tuning`
  object, so the driving, sim, snapshot and server paths pick the stats up unchanged.
- Boost and Luck read `kart.tuning` (or `boost.gain`) at the point where they act.

**Tech Stack:** Vanilla JS (ES modules), Three.js client, deterministic sim (`src/sim/math.js` only),
`node:test` and vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-car-stats-design.md`

## Global Constraints
- **Deterministic sim code.** No `Math.random`, `Math.sin`, `Math.hypot` and so on in files the server bundle
  includes. Use `src/sim/math.js`. After sim edits, run `npm run build:server-sim`.
- **Bars and budget.** Bars are integers from 1 to 10, `t = (bars − 5) / 5`, and every class totals 26 bars.
- **Starting coefficients:**
  - speed `1 + 0.04t`
  - accel `1 + 0.30t`
  - turn `1 + 0.22t`
  - GOOD opens at `0.70 − 0.08t`
  - PERFECT opens at `0.90 − 0.04t`
  - boost gain `1 + 0.15t`
  - luck shift `t < 0 ? 0.10t : 0.30t`
- **Not scaled by boost gain:** Soda Siphon's stolen boost (`gameplay-core.js:558`) and the Test Drive entry
  boost (`session.js:98`, `world.js:276`).
- **Fixed points:** TOO LATE stays at meter 1.0. Drivers stay cosmetic.
- **Don't edit the generated `src/concept-roster.js`.** `npm test` runs `build-concept-roster.mjs --check`.

## Review Focus
1. **A snapshot restore keeps `boost.gain`.** A wire snapshot carries no gain, so after `applySnapshot` a
   Booster still gets its longer boosts. Test this in Task 2.
2. **Resets keep the gain.** A respawn or interrupt reset (`interruptBoost`, `session.js:206`,
   `world.js:370`) leaves `boost.gain` intact. Test this in Task 2.
3. **The HUD and timing lamp follow the car's own windows.** A Booster sees READY at its own GOOD point, not
   at the fixed 0.70. Test this in Task 4 with a unit test on the label helper.
4. **Turning at bar 9 stays inside the steering geometry.** `qa/steering-edges.mjs` must pass with Drifter
   cars. Run it in Task 5.
5. **Luck never pushes `trailing` outside 0–1,** so item weights stay non-negative. Test this in Task 3.

### Task 5: Balance testing and tuning

**Files:**
- Create: `qa/car-classes.mjs`
- Modify: `src/car-classes.js` (bars and coefficients, only as the results require)

**Interfaces:**
- Consumes:
  - `createSimWorld({ course, seed, finishRule:'all_racers', seats })`. Seats are
    `{kind:'ai', gridIndex:i, car:<id>}`.
  - `CAR_CLASSES` and `CLASS_OF`.

- [ ] **Step 1: Write the QA script.** It has two parts.
  - **Same-class races:** for each class and each of the 3 circuits, run 4 seeds of six AI karts that are
    all one car of that class. Use the class's rival car where one exists, otherwise the first car in the
    class. Record the mean finish time.
  - **Mixed packs:** on each circuit, run 8 seeds of six karts, one per class, rotating grid slots by
    seed. Record each class's wins and mean position.
  - **Report:** for each class, the mean time against the all-class mean (%), the win share, the
    GOOD/PERFECT rate, and the mean `trailing` of rolled items.
  - **Assertions:**
    - every class mean is within 1.5% of the overall mean;
    - no class wins more than 30% of mixed races;
    - no class is fastest on all 3 circuits.
- [ ] **Step 2: Run it.** Run `node --import ./tests/register-sdk-hook.js qa/car-classes.mjs`.
  It is expected to fail at first. Record the report.
- [ ] **Step 3: Tune.** Move one bar at a time between stats inside the failing class, keeping 26. Adjust a
  coefficient only if bars alone can't close the gap. Re-run after each change.
  - Keep a short log of each change and its result in the commit message.
  - Also run `qa/steering-edges.mjs`: Turning 9 must pass on every chassis. If it fails, lower the `turn`
    coefficient.
- [ ] **Step 4: Verify.** Run `npm run build:server-sim && npm test && npm run test:qa`.
  Expected: all green, including `qa/car-classes.mjs`. Then update the spec's class table and the README
  to the final bars.
- [ ] **Step 5: Commit** with the message "Balance car classes with AI races", and the tuning log in the body.
